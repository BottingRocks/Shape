# Signals

A signal is one browser measurement that the Shape client collects and adds to its payload. Each emission starts with a 4-byte random seed, then writes its fields (numbers, strings, single bytes) XOR-masked with a stream seeded from that value and the signal's mask constant (its salt). Field order, masks, flag bit positions and slot addresses change with every build, so the layout of one build comes from the CLI:

```sh
shape signals <program.js> --json
```

The input is a deobfuscated program (`shape trace program` output). The report names every recognized slot with one of the canonical signal names below and its fields with the names used on these pages.

## Reading a schema

See [schema format](schema.md) for the report layout: build header, slot address, routing (positional or by name), masks, field order, field types, flags with bits, and diagnostics.

## Per-signal pages

Each signal has an explanation page (`<signal>.md`: what it collects, why, its fields, and where it appears in a schema) and a static JavaScript data-shape example (`<signal>.js`). The default export is the payload itself: a data literal, including bare scalars and arrays. These modules contain no collectors or encoding logic.

Comments label captured values versus illustrative values derived from the card and readable projection. A captured default documents one observation, not a complete runtime schema. Additional named data exports illustrate message alternatives, conditional fields and representative items absent from an empty capture. No-data slots export `undefined`; an illustrative `undefined` variant can also document a path that emits nothing. JavaScript numeric constants such as `NaN` preserve special measurement values without byte metadata. The Markdown field tables and [schema format](schema.md) remain the wire reference; data examples omit encoding-only lengths, prefixes and padding, while retaining meaningful measurements.
